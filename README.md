# NyaRemoteControl for Windows

一个程序两种用法：用它**远程控制别的电脑**；开启“允许远程控制本机”后，**别人也能控制这台电脑**（像向日葵、ToDesk 一样，不再分客户端和被控端两个软件）。

网络穿透不在本程序范围内。请用 Tailscale / EasyTier / ZeroTier 等工具把电脑组到同一个网络，连接对方在该网络里的 IP。手机上控制电脑用 Android 版（单独的仓库，只能控制别人）。

被控端用一个端口（默认 47100）：画面、声音、键鼠走 **UDP**（QUIC），文件传输（发送文件、复制粘贴文件 / 文件夹、打印）走 **TCP**（TLS 加密，同样校验证书，每个文件有 SHA-256 校验）。用 frp 等工具做端口转发时，UDP 和 TCP 都要转发，而且外部端口号相同。TCP 不通时文件仍会经 UDP 传输，只是传大文件时更容易影响画面。

连接方式（设置 → 连接方式，或会话中工具条“画面模式”菜单）：**自动**（默认，优先 UDP；UDP 连不上、或丢包连续 20 秒超过 10% 时改用 TCP，UDP 恢复后自动换回）、**仅 UDP**、**仅 TCP**（整个会话走 TCP，适合 UDP 不通或很差的网络，网络差时延迟比 UDP 高）。统计信息里能看到当前走的是哪一种。

## 安装

运行安装包 `NyaRemoteControl_<版本>_x64-setup.exe`（需要 64 位 Windows 10 或更高版本；主界面需要 Windows 自带的 WebView2 运行库，精简版系统缺少时会提示下载地址）：

- 装到 `C:\Program Files\NyaRemoteControl`，创建开始菜单和桌面快捷方式。
- **“允许远程控制本机（安装后台服务）”默认不勾选**。只用来控制别的电脑时不需要它；以后也可以在程序的“本机”页里点“开启远程控制”（会请求一次管理员权限）。开启后作为 Windows 服务在后台运行：开机自启，锁屏、登录界面和 UAC 弹窗也能操作。
- 升级时直接覆盖安装；已经开启了远程控制的电脑保持开启。已保存的设备和设置（`%APPDATA%\NyaRemoteControl\client`）、配对信息和证书（`C:\ProgramData\NyaRemoteControl`）都保留。
- **从 0.7 以前的版本升级**（以前客户端和被控端是两个安装包，装在 `...\NyaRemoteControl\Client` 和 `...\Server`）：安装新版本即可，旧的两份程序、快捷方式和卸载项会被删除，服务改由新目录运行，配对信息不变。旧版本的自动更新也会直接装上新版本。
- 卸载时会删除服务，可选同时删除 `C:\ProgramData\NyaRemoteControl`；`%APPDATA%` 里的设置不删。
- 静默安装：`/S`；加 `/SERVICE` 同时开启远程控制。

## 程序组成

| 文件 | 作用 |
|---|---|
| `NyaRemoteControl.exe` | **主程序**，双击打开的是它：设备、连接设置、远程窗口，以及“本机”页（管理被控服务） |
| `nya-server-svc.exe` | **远程控制服务**：Windows 服务、采集进程、开发模式、诊断。不用直接运行它 |
| `nya-server.exe` | **命令行**：管理本机的被控服务（见下文），也是服务自动更新时用的更新程序。不带参数运行会打开主程序的“本机”页 |
| FFmpeg DLL | 主程序解码和服务编码共用 |

主程序和服务是分开的进程：主程序关着服务照样运行；主程序通过本机的控制管道（`\\.\pipe\NyaRemoteControl.control`）和服务通信，查看状态、改设置、管理配对都是**立即生效**的。

**托盘与开机启动**：关闭主窗口时程序缩到屏幕右下角的托盘里继续运行（远程会话不断开）；点托盘图标重新打开，右键选“退出”才真正关闭（“关于与诊断”里可以改成关闭即退出）。再次双击程序只会把已经运行的那个调出来。“开机自动启动”（同一页，默认关）让主程序在登录 Windows 后直接在托盘里运行；它和远程控制服务无关——服务随电脑启动，不需要登录。

# 控制别的电脑

## 连接

双击 `NyaRemoteControl.exe` 打开主界面（需要 Windows 自带的 WebView2 运行库；精简版系统缺少时会提示下载地址）：

- **设备**：顶部输入框直接输入地址连接（例如 `100.64.0.2` 或 `100.64.0.2:47100`）；已保存的设备以卡片显示，点卡片或“连接”即可。“⋯”菜单里可以打开这台设备的连接设置、改名、复制地址、删除。
- **连接设置**：被控端显示器（虚拟显示器 / 隐私屏）、画面模式、码率、声音、麦克风、键盘捕获、剪贴板等，改完点“保存”。右上角选择“默认设置（所有设备）”或某一台设备。
- **关于与诊断**：本机名称、本机硬件解码情况、运行诊断、打开日志目录。

### 每台设备单独的设置

- 没有单独设置的设备使用“默认设置”。在连接设置右上角选中某台设备再保存，它就有了自己的设置，不影响其他设备；“改回使用默认设置”可以撤销。
- 连接后在工具条里改的**模式（办公/游戏）、被控端显示器（虚拟屏/隐私屏）、网络变差时的策略、麦克风、键盘捕获**会自动记在这台设备的单独设置里，下次连接它时沿用。

### 名称

- **被控端的名称**：默认显示被控端自己设置的名称（被控端的“本机 → 被控设置 → 显示名称”，没设置时是计算机名），被控端改名后客户端下次连接时跟着变。也可以在“⋯ → 改名”里起一个只在本机用的名字；改名时留空则恢复使用被控端的名称。
- **本机的名称**：在“关于与诊断 → 本机名称”里设置（留空 = 计算机名），被控端的“已配对客户端”和连接记录里显示这个名字，下次连接时更新。

连接后远程画面在单独的远程窗口里打开，主界面保留（远程期间关闭主界面只会把它最小化）。断开或关闭远程窗口都会结束连接并回到主界面。

### 工具条

远程窗口顶部中间有一个小标签（“▾ 被控端名称”）。鼠标在标签上停一下或点一下，工具条就会出现；离开工具条后自动收起。只有这个小标签会打开工具条，窗口顶部其他地方和工具条原来所在的位置都照常点击远程画面。标签挡住了想点的内容时，按住它左右拖到别处即可。Ctrl+Alt+Shift+T 让工具条一直显示。

工具条从左到右：

| 分组 | 内容 |
|---|---|
| 连接 | 被控端名称、端到端延迟（颜色表示好坏，点击显示统计信息）、观看人数 |
| 画面 | 显示器菜单（切换屏幕、新窗口、虚拟显示器、一键隐私屏）；模式菜单（办公 / 游戏、网络变差时的策略、当前码率） |
| 输入 | 键盘捕获、锁定鼠标（相对鼠标）、麦克风；“⋯”：发送文件、Ctrl+Alt+Del、USB、统计信息 |
| 窗口 | 全屏、断开 |

窗口较窄时，“锁定鼠标”和“麦克风”收进“⋯”。观看别人操作时，输入相关的按钮不可用。

也可以直接用命令行：

```powershell
.\NyaRemoteControl.exe connect 100.64.0.2 --name 家里台式机
.\NyaRemoteControl.exe connect 家里台式机 --mode game --fullscreen
```

**第一次连接需要配对码**：在被控端的“本机 → 概览”里查看（需要管理员权限；也可以运行 `nya-server pair`）。配对成功后客户端会保存被控端的证书指纹，之后连接不再需要配对码；如果证书指纹变了，客户端会拒绝连接，以防止中间人攻击。

**扫码 / 链接配对**：更省事的办法是在被控端“本机 → 概览 → 配对码”点“扫码 / 链接配对”。手机版直接扫二维码；电脑上把“配对链接”（`nyaremote://pair?…`）发给控制端那台电脑，粘贴到“添加设备”或设备页顶部的地址框（刚复制的链接会自动填入），或者直接点开链接（安装版注册了这种链接，点开后会先确认）。链接里带着被控端的地址、证书指纹和配对码：客户端同时尝试所有地址，用证书指纹认准被控端，自动完成配对。链接和二维码等同于配对码本身，不要公开发布。通过端口转发或 frp 从外网访问时，在“被控设置 → 对外地址”里填上外网地址（如 `frp.example.com:7000`），它会排在链接地址的最前面。

网络断开后客户端会自动重连，最多持续 2 分钟。

## 同时连接多台、多人连接同一台

- **同时连多台被控端**：远程期间回到主界面再连另一台，每台各自一个远程窗口；同一台不能连两次。
- **别人已经在操作这台被控端**时，你连上后是**观看**：能看到画面，但不能操作，窗口上方显示“正在观看 · 某某 正在操作”。点“接管操作”由你来操作（对方改为观看），点“顶掉对方”则同时断开对方。操作的人工具条上会显示“N 人观看”。
- 观看时只显示被控端的主画面；需要被控端也是新版本。

## 被控端显示器：虚拟显示器 / 隐私屏

在“连接设置 → 被控端显示器”里设置，连接后也可以在工具条显示器菜单的“显示设置”里随时修改。三项可以自由组合：

| 设置 | 说明 |
|---|---|
| 虚拟显示器：不用 / 1–4 个 | 在被控端新建虚拟显示器，第一个设为主显示器；有多个时在工具条“显示器”里切换查看 |
| 被控端物理显示器：保持显示 / 关闭（黑屏） | 保持显示 = 虚拟屏和物理屏同时存在（扩展屏）；关闭 = 只保留虚拟屏，被控端屏幕黑屏 |
| 屏蔽被控端本地键盘鼠标 | 被控端旁边的人无法操作 |

工具条显示器菜单里的**隐私屏**一键设为：1 个虚拟显示器 + 物理显示器黑屏 + 屏蔽本地键鼠。“恢复被控端原样”则撤销全部。

## 多窗口：同时看被控端的多个显示器

被控端有多个显示器（物理的、虚拟的都算）时，可以每个显示器一个窗口，同时显示：

- 连接后在工具条的显示器菜单里，点某个屏幕旁边的“新窗口”；
- 或者点显示器菜单里的“＋ 新建虚拟屏，在新窗口显示”：被控端多建一个虚拟显示器并直接在新窗口里打开。几个窗口可以并排放在本机的同一块屏幕上（例如一块 4K 屏放两三个窗口），不需要本机有多块屏幕；
- 或者在“连接设置 → 多个显示器的显示方式”选“每个显示器一个窗口”，连接后自动为每个显示器打开窗口（新出现的虚拟显示器也会自动打开）。

虚拟显示器的分辨率选“跟随窗口”时，每个虚拟屏各自跟随显示它的那个窗口的大小（全屏时为所在屏幕的大小）。统计面板（Ctrl+Alt+Shift+S）列出每个窗口那一路画面的数据。

每个窗口可以单独拖到本机的不同屏幕、单独全屏；鼠标操作对应窗口里的那块屏幕，键盘发给被控端。关闭额外的窗口只停止那一路画面，不断开连接；主窗口的“断开”结束整个连接。多一个窗口就多一路视频，带宽和被控端编码负担相应增加（自动码率会在几路之间分配）。需要客户端和被控端都是新版本。

- 虚拟显示器的分辨率可以**跟随窗口**（调整窗口大小或全屏后自动跟随，画面 1:1 最清晰）、**跟随本机屏幕**或**固定**，还可以沿用本机的缩放比例（如 150%）。不会改动被控端物理显示器的分辨率。
- 第一次用某个不常见的分辨率时，被控端的虚拟显示器会重启一下（约 2 秒），之后切换是即时的。
- 断开后被控端自动恢复原来的显示器布局（为了网络闪断时不来回切换，会等 15 秒）。
- 需要被控端在“本机 → 可选组件”里安装**虚拟显示器**，并以服务模式运行；不满足时会提示原因并自动改用物理显示器。
- 隐私屏无法屏蔽被控端本地按下的 Ctrl+Alt+Del（Windows 的安全设计），但本地屏幕仍然是黑的。

被控端显示器开启了 HDR 时，画面默认在被控端转换为 SDR 再传输（不再发白、过曝），统计面板里会注明。如果本机显示器也开着 HDR，并且“连接设置 → HDR 直通”打开（默认打开），则直接用 HDR10（HEVC 10 bit）传输，高光和色彩保持 HDR；需要被控端用 N 卡 / Intel 核显 / AMD 显卡硬件编码。远程窗口拖到不是 HDR 的显示器上时，本机自动转换为 SDR 显示。

## 文件和剪贴板

- **复制粘贴文件（双向，支持文件夹）**：在一边复制文件或文件夹（Ctrl+C），到另一边粘贴（资源管理器里 Ctrl+V，或粘贴到支持文件的程序里），就会把它们传过去。复制时只告诉对方有哪些文件，粘贴时才真正传输，不粘贴就不占带宽；传输进度显示在窗口右下角。
  - 粘贴过来的文件先接收到 `%LOCALAPPDATA%\NyaRemoteControl\clipboard`（一天后自动清理），再由资源管理器复制到你粘贴的位置。
  - 连接断开后，对方复制的文件就不能再粘贴了，需要重新复制。
  - 需要客户端和被控端都是新版本；和旧版本连接时，仍是原来的方式（被控端复制后点“下载到本机”）。
- **发送文件到被控端**：也可以把文件拖进窗口，或点工具条“⋯”里的“发送文件…”。文件保存在被控端当前用户的 `下载\NyaRemoteControl`，并放入被控端剪贴板。
- **剪贴板文字和图片**双向自动同步（截图后直接粘贴即可）。
- 以上都受“连接设置 → 同步剪贴板”开关控制。

## 共享文件夹（在被控端显示为一个盘）

在“连接设置 → 共享文件夹”里添加本机的文件夹（可以设为只读、改在被控端显示的名称）。连接后这些文件夹出现在被控端的一个盘符里（例如 Z:，每个文件夹是其中的一个目录），被控端的程序可以直接打开、编辑、保存，不需要先复制过去。

- 被控端需要在“本机 → 可选组件”里安装“文件夹挂载”（WinFsp）；没装时连接后会提示。
- 只有正在操作的客户端的文件夹会挂载；断开后盘符消失。
- 被控端只能看到你共享的文件夹里面的内容；只读的文件夹不能被修改。
- 每次读写都要经过网络，大文件在网络较慢时会比较慢；只是传文件的话，复制粘贴文件更快。

## 被控端打印，本机打出来

被控端在“本机 → 可选组件”里安装“打印到客户端”后，会多一台打印机“打印到 NyaRemoteControl 客户端”。在被控端的任何程序里选它打印，内容会以 PDF 发到正在操作的客户端，保存在 `下载\NyaRemoteControl\打印`，然后按“连接设置 → 被控端打印时”的选择：

- **用本机默认打印机打印**（默认）：不需要 PDF 阅读器；打印失败时会打开 PDF。
- **打开 PDF**：用本机的 PDF 阅读器打开，自己决定怎么打印。
- **只保存到下载文件夹**。

需要被控端以服务模式运行。

## USB 设备透传

工具条“⋯ → USB”把本机的 USB 设备（U 盾、加密狗、打印机等）交给被控端使用。需要本机安装 usbipd-win（开源免费，可选组件）：面板里点“一键安装”，会弹出一次管理员权限确认。安装包随程序放在 `drivers` 文件夹里，安装时优先用它（校验通过才用），不需要联网；没有时才从 GitHub 下载。被控端也需要在“本机 → 可选组件”里安装 USB/IP。

## 快捷键（Ctrl + Alt + Shift + …）

| 键 | 功能 |
|---|---|
| T | 工具条一直显示 / 恢复自动收起 |
| Q | 捕获 / 释放键盘。捕获时 Alt+Tab、Win+D、Win+E 等组合键发给远程电脑（在云电脑里运行时也一样） |
| S | 显示 / 隐藏统计面板：帧率、码率、端到端延迟、编码/解码耗时（中位数和最近 10 秒的 P99）、声音缓冲 |
| M | 切换办公模式 / 游戏模式 |
| R | 相对鼠标模式（适合 FPS 游戏，鼠标会被锁在窗口内） |
| F | 全屏 / 窗口 |
| D | 发送 Ctrl+Alt+Del（需要被控端以服务模式运行） |
| 1–9 | 切换被控端的第 N 个显示器 |
| X | 断开连接 |

## 两种模式

- **办公模式**（默认）：本机显卡能硬件解码时，自动使用 HEVC 4:4:4，文字清晰；画面静止后会再补发几帧来提高清晰度。画面不变时几乎不占带宽。
- **游戏模式**：4:2:0，高帧率（跟随显示器刷新率），码率固定，延迟最低，允许画面撕裂。

### 画面传输方式

“连接设置 → 画面传输方式”：

- **自动**（默认）：游戏模式用“数据报 + 纠错”，办公模式用可靠传输。
- **可靠传输**：不会丢画面，但网络丢包时要等重传，会卡一下。
- **数据报 + 纠错**：每帧额外发送 10–50% 的纠错数据（按实际丢包率自动调整），丢了一部分也能还原；还原不了就跳过这一帧并马上补一个完整画面，不会因为等重传而卡住。

统计面板里“传输”一行显示纠错比例、丢包率和恢复 / 丢掉的帧数。需要客户端和被控端都是新版本。

## 配置 `%APPDATA%\NyaRemoteControl\client\client.toml`

```toml
client_name = ""       # 本机名称，被控端里显示；空 = 计算机名

[defaults]             # 默认设置；[[hosts]] 里可以有自己的 settings（字段相同）
mode = "office"        # office | game
fullscreen = false
display = 0            # 被控端显示器编号，0 = 主显示器
bitrate_kbps = 0       # 0 = 由被控端决定
max_fps = 0            # 0 = 本机显示器刷新率
encoder = "auto"       # auto | nvenc | qsv | amf | software
codec = "auto"         # auto | h264 | hevc | av1
chroma = "auto"        # auto | 420 | 444
audio = true
clipboard = true
hw_decode = true
vd_count = 0          # 虚拟显示器数量（0–4）
physical_off = false   # 有虚拟显示器时关闭被控端物理显示器
block_input = false    # 屏蔽被控端本地键盘鼠标
vd_size = "window"     # 虚拟显示器分辨率：window（跟随窗口）| screen（跟随本机屏幕）| fixed
vd_width = 1920        # vd_size = "fixed" 时使用
vd_height = 1080
vd_scale = true        # 虚拟显示器使用本机的缩放比例
mic = false            # 连接后打开麦克风
grab_keyboard = true   # 连接后捕获键盘（Alt+Tab、Win 键组合发给被控端）
transport = "auto"     # 连接方式：auto（优先 UDP，不通或丢包严重时用 TCP）| udp | tcp

[[hosts]]              # 连接成功后自动保存
name = "家里台式机"
address = "100.64.0.2"
fingerprint = "…"
server_name = "DESKTOP-ABC"  # 被控端自己设置的名称
custom_name = true     # true = 用 name；false = 跟随 server_name

[hosts.settings]       # 这台设备的单独设置（没有则用 [defaults]）
mode = "game"
```

# 让别人控制本机（“本机”页）

被控端负责截屏、硬件编码（NVIDIA NVENC / Intel QSV / AMD AMF，没有独显时用软件编码）、系统声音、键鼠注入和剪贴板同步，由后台服务完成。

## 开启远程控制

主程序左侧“本机 → 概览”里点“**开启远程控制**”（或安装时勾选“允许远程控制本机”）：安装并启动服务 `NyaRemoteControl`，并自动完成：防火墙放行 UDP 和 TCP 47100（画面、声音、操作走 UDP，文件传输走 TCP）；开启 `SoftwareSASGeneration` 策略（让远程 Ctrl+Alt+Del 可用）；数据目录 `C:\ProgramData\NyaRemoteControl` 仅允许 SYSTEM / 管理员访问。不想再被控制时，在“被控设置”最下面点“关闭远程控制”（卸载服务，配对信息保留）。

**配对码、设置和已配对客户端只有管理员能看、能改**：配对后对方拿到的是服务（SYSTEM）的权限，所以普通权限打开的主程序在“本机”页只显示服务状态和当前连接，点“以管理员身份重新打开”后才显示其余内容（需要先断开正在进行的远程连接）。

“本机”页：

- **概览**：开启远程控制；服务状态与启动 / 停止 / 重启；配对码（可复制、重新生成；配对二维码和配对链接）；当前连接（客户端、地址、画面参数，可断开）；证书指纹；最近事件
- **已配对客户端**：查看、移除（正在连接的会被断开）
- **被控设置**：端口、监听地址、对外地址（只用于配对链接）、名称、编码器、码率、帧率、声音、日志级别（服务运行中保存即生效）；重新安装服务 / 关闭远程控制
- **可选组件**：虚拟显示器、虚拟声卡、手柄、USB 透传、文件夹挂载（WinFsp）、打印到客户端，一键安装
- **被控诊断**：运行诊断并查看 / 复制结果
- **服务日志**：服务、采集进程、虚拟显示器测试的日志，打开日志目录

服务模式下可以操作锁屏、登录界面和 UAC 弹窗，注销、切换用户后连接也不会断。

## 开发模式

```powershell
.\nya-server-svc.exe standalone
```

以当前用户身份单进程运行，窗口中直接显示配对码。**开发模式无法操作锁屏、登录界面和 UAC 弹窗**，也不能远程发送 Ctrl+Alt+Del。下面的 `nya-server` 命令同样可以管理运行中的开发模式（控制管道 `NyaRemoteControl.control.standalone`）。

## 常用命令（nya-server）

以**管理员身份**打开终端，进入程序目录。`nya-server install` 开启远程控制（安装并启动服务，最后打印配对码），其余命令优先作用于运行中的服务（其次是运行中的开发模式），都没运行时直接读写数据目录；加 `--data-dir` 则总是直接读写指定目录。

| 命令 | 说明 |
|---|---|
| `nya-server status` | 运行状态、监听地址、当前连接、最近事件 |
| `nya-server pair` | 查看配对码（服务模式需要管理员） |
| `nya-server pair --reset` | 重新生成配对码，立即生效，已配对的客户端不受影响 |
| `nya-server clients` | 列出已配对的客户端 |
| `nya-server clients --remove <指纹前缀>` | 移除某个客户端（正在连接的会被断开） |
| `nya-server config` | 查看设置 |
| `nya-server config --set port=47101 --set encoder=nvenc` | 修改设置，服务运行中立即生效 |
| `nya-server disconnect` | 断开当前的远程连接 |
| `nya-server diag` | **诊断**：显卡、显示器、各编码器能力和耗时、截屏测试、跨显卡传输耗时、音频。结果保存到 `nya-diag.txt` |
| `nya-server uninstall [--purge]` | 卸载服务；`--purge` 同时删除证书、配对信息和日志 |

## 配置 `server.toml`

服务模式在 `C:\ProgramData\NyaRemoteControl\server.toml`，开发模式在 `%LOCALAPPDATA%\NyaRemoteControl\server\server.toml`。首次运行时自动生成：

```toml
port = 47100
bind = "::"                 # 改成组网 IP（如 100.x.y.z）则只接受该网卡的连接
name = ""                   # 显示给客户端的名字，空 = 计算机名
encoder = "auto"            # auto | nvenc | qsv | amf | software
office_bitrate_kbps = 0     # 0 = 按分辨率自动
game_bitrate_kbps = 0
max_fps = 144
audio = true
log_level = "info"
```

建议用“本机 → 被控设置”或 `nya-server config --set` 修改：服务运行中立即生效（画面相关设置会让采集进程重启一下；改端口或监听地址会断开当前连接，并自动更新防火墙规则；日志级别在服务重启后生效）。直接编辑文件则需要重启服务：`sc stop NyaRemoteControl`，然后 `sc start NyaRemoteControl`。

## 日志

保存在数据目录下的 `logs\`（`service.*.log`、`helper.*.log`、`standalone.*.log`；“本机 → 服务日志”里可以查看），保留 7 天。FFmpeg 自身的输出默认关闭（探测和降级时的报错是正常现象）；排查编码问题时可设置环境变量 `NYA_FFMPEG_LOG=warning`（或 `verbose`）后再运行。排查问题时请连同 `nya-diag.txt` 一起提供。

## 虚拟显示器、隐私屏和 HDR

- 客户端可以在被控端新建 1–4 个**虚拟显示器**（第一个设为主显示器，分辨率由客户端决定，可跟随客户端窗口），选择物理显示器保持显示（扩展屏）还是关闭（黑屏），以及是否屏蔽本机键盘鼠标（三项合起来就是“隐私屏”）。需要在“本机 → 可选组件”里安装虚拟显示器，并以服务模式运行。
- 虚拟显示器平时处于停用状态，只在有客户端要求时启用；客户端断开 15 秒后停用，Windows 恢复原来的显示器布局。采集进程异常退出时，下次启动会自动恢复。
- 虚拟显示器驱动的设置文件 `C:\VirtualDisplayDriver\vdd_settings.xml` 由本程序在每次连接时重写（分辨率列表），手动修改会被覆盖。
- 显示器开启 HDR 时，按 HDR 格式截屏并在显卡上转换为 SDR（以 Windows 设置里的“SDR 内容亮度”为白色）后再编码，客户端看到的画面和 SDR 显示器上一样，不再发白过曝。`nya-server diag` 会列出哪些显示器开了 HDR。

## 多个客户端同时连接

- 第一个连上的客户端**操作**被控端；之后连上的客户端**观看**：看到同一个画面，但不能操作（键鼠、剪贴板、USB、显示设置都只听操作者的）。
- 观看的客户端可以“接管操作”（原来的操作者改为观看），或“顶掉对方”（原来的操作者被断开）。操作者断开后，最早连上的观看者自动接管。
- “本机 → 概览 → 当前连接”列出操作者和所有观看者；“全部断开”断开所有客户端。
- 旧版客户端（不支持观看）连上时仍会顶掉所有已连接的客户端。

## 编码器选择（多显卡 / 笔记本）

- 截屏必须在显示器所连接的显卡上完成；编码可以在任意显卡上完成。
- 默认优先使用同一块显卡编码（不需要拷贝）。如果办公模式需要 4:4:4 而这块显卡不支持（例如较老的核显），会自动改用 N 卡编码，画面通过内存在两块显卡之间传递。
- 如果某个编码器在运行中连续出错，本次运行会自动换用下一个方案。

# 更新

整个程序（主程序、服务、命令行）是同一个版本、同一个安装包。

- 主程序启动时到 GitHub Releases 查看有没有新版本（“关于与诊断”里可以关掉），有就在主界面顶部提示。点“立即更新”：下载安装包并核对 SHA-256，请求一次管理员权限，主程序关闭、静默安装（开启了远程控制时服务会停止、更新后重新启动，远程连接断开约 1 分钟后自动重连），完成后自动重新打开。便携版（不是用安装包装的）会打开发布页，请手动下载。
- 没人在电脑前的被控端也能自己更新：服务每 12 小时检查一次（“本机 → 被控设置 → 服务自动检查新版本”），用 `nya-server update --install` 安装。这时服务下载安装包并核对 SHA-256，然后启动独立的更新程序（`C:\ProgramData\NyaRemoteControl\update\nya-updater.exe`，不随服务停止）：
  1. 备份当前程序文件；
  2. 静默运行安装包（停止服务、替换文件、重新注册并启动服务）；
  3. 检查新版本的服务在 2 分钟内正常应答；
  4. 不正常就恢复备份、重新注册并启动旧版本的服务；
  5. 无论结果如何，最后都确保服务在运行。

  结果显示在“最近事件”里，过程记录在 `C:\ProgramData\NyaRemoteControl\logs\update.log`。这种更新会关掉正在运行的主程序，完成后不会自动重新打开。

# 构建

依赖同级目录的 `../common`（公共仓库）和 `../third_party/ffmpeg`（运行 `../common/scripts/fetch-ffmpeg.ps1` 下载）。

```powershell
cargo build --release      # 会自动用 npm 构建主界面（../common/web），需要安装 Node.js
.\scripts\package.ps1      # 生成 dist\NyaRemoteControl（3 个 exe + 3 个 FFmpeg DLL + 可选组件安装包）
```

主界面是 `../common/web` 里的 Svelte 页面（client.html，“本机”部分在 `src/host`），编译时嵌入 `NyaRemoteControl.exe`。改界面时可以在那里运行 `npm run dev`，在浏览器里用示例数据预览；或者设置环境变量 `NYA_WEB_DEV=http://localhost:5173` 再运行主程序，直接加载开发服务器。

本仓库是一个 Cargo workspace：

| 目录 | 包 | 产物 |
|---|---|---|
| `app/` | `nya-app` | 主程序 `NyaRemoteControl.exe`（界面、远程窗口、解码，“本机”页的逻辑在 `app/src/app/host.rs`） |
| `host/` | `nya-server` | 远程控制服务 `nya-server-svc.exe`（服务、采集进程、网络、编码） |
| `core/` | `nya-server-core` | 共用的被控端部分：配置、配对数据、路径、日志、安装、控制管道协议（`core/proto/control.proto`）和它的客户端 |
| `cli/` | `nya-server-cli` | 命令行和更新程序 `nya-server.exe` |

`cli` 和 `core` 不能依赖 `host` 或 `app`，否则会把 FFmpeg 链接进来，而更新程序要在没有 FFmpeg DLL 的目录里运行。`app` 只依赖 `core`，不依赖 `host`。`control.proto` 是兼容性接口：升级过程中主程序、命令行和服务可能版本不同，只能新增字段和请求。

## 安装包、版本和发布

- **版本号**：`VERSION` 文件（`主.次.修订`，可带 `-beta.1` 这样的后缀），和四个 `Cargo.toml`（`scripts/versions.ps1` 列出）的版本保持一致；主程序、服务和命令行同一个版本。显示的版本带提交号，例如 `0.7.0 (5b67ace0)`（`+` 表示有未提交的改动）；exe 的“属性 → 详细信息”里也能看到版本。
- **本地打安装包**：`.\scripts\build-release.ps1`（需要 NSIS：`winget install NSIS.NSIS`），在 `release\` 生成安装包 `NyaRemoteControl_<版本>_x64-setup.exe`、便携版 zip 和对应的 `.sha256`。缺少的 FFmpeg、ViGEmClient、驱动安装包会自动下载。
- **发布新版本**：`.\scripts\release.ps1 0.7.1`：改 `VERSION` 和 `Cargo.toml`，把当前 common 的提交记到 `COMMON_REF`（发布构建用这个版本的 common；common 要先推送），提交并打 tag `v0.7.1`。再 `git push origin HEAD v0.7.1`（或加 `-Push`），GitHub Actions 会构建安装包并发布到 Releases；带后缀的版本发布为预发布版。
- **CI**：推送到 main 或提 PR 时，`.github/workflows/ci.yml` 用最新的 common 编译、运行测试并打一个便携 zip（在 Actions 的构建产物里）。
